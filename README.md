# mfcapture

## 概要
本プロジェクトは、H.264 等の圧縮フォーマットを出力する Web カメラ（RICOH THETA V など）から高速に映像をキャプチャし、OpenCV 等を用いて画像処理を行うためのキャプチャ・キャリブレーションアプリケーションです。
Windows 環境において Microsoft Media Foundation (MSMF) を直接利用し、キャプチャおよびデコード処理を高速化することを目的としています。

## 特徴と現在のアーキテクチャ
- **Media Foundation の直接利用 (`CamMf`)**: OpenCV の `cv::VideoCapture` によるパフォーマンス低下（低フレームレート化）を回避するため、キャプチャおよびデコードを OpenCV から独立させて実装しています。
- **MFT を用いた手動デコード**: H.264 や MJPG フォーマットに対して、MFT (Media Foundation Transform) デコーダとカラーコンバータを構築し、CPU メモリへ直接展開することでオーバーヘッドを最小化しています。
- **初期化の遅延評価 (Lazy Initialization)**: デバイス認識時やフォーマット一覧取得時にはデコーダの初期化を行わず、ユーザーが明示的にキャプチャ開始を指示したタイミングで初期化・フォーマット適用を実行します。これにより、カメラ列挙時のフリーズや競合エラーを回避しています。
- **フレーム処理モードの動的切り替え**: 用途に応じて、全フレームを漏らさず処理する「全フレーム処理モード」と、不要なバッファリングを排除し常に最新のフレームを表示する「レイテンシ優先モード」を UI から実行時に切り替えることができます。
- **スレッドセーフと堅牢なリソース管理**: キャプチャスレッドとメインスレッドの連携における排他制御とアトミック変数を利用したフラグ管理、さらに RAII 等を活用した厳密なメモリリーク・バッファオーバーフロー防止策を実装し、長時間の連続稼働に耐える設計となっています。

## 既知の課題・仕様
- **H.264 キャプチャと他プレイヤーとのごくわずかな遅延差**: 
  本プロジェクトでは OpenGL で処理するために「MFT から直接 CPU メモリへ展開する」アーキテクチャを採用しています。そのため、MPC-HC などのような「ハードウェアデコード (DXVA) + GPU メモリでの Zero-copy レンダリング」を行っている専用プレイヤーと比較すると、メモリのコピペや CPU でのカラー変換が挟まる分、ごくわずかに遅延が大きく感じられる場合があります。
  しかし、`CODECAPI_AVLowLatencyMode` を有効にしてデコーダのバッファリングを防ぎ、最新フレームを即座に取得し続ける機構を実装しているため、現状の要件下では**限界に近い低遅延と安定したストリーミング**を達成しています。
